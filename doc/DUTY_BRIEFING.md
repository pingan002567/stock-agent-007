# 定时值班任务：统一四段输出契约

> 背景：五个定时任务此前各自写自由文本，落盘时用「取正文第一行当结论」的启发式
> 硬套进统一模板 —— 结果每份报告的"结论"其实是各自的标题行（`收盘体检 10-23 15:15**`、
> `1. 市场环境（截至 10-22 收盘）**` …），章节数也从 4 到 6 不等。

## 一、契约

所有定时任务输出**固定四段**，任务差异只体现在「依据」和「动作」里写什么：

| 段 | 内容 | 约束 |
|---|---|---|
| 1. 结论 | 今天该做什么 / 或明确「今天不用动」 | 一句话，≤40 字 |
| 2. 依据 | 判断依据 | ≤5 条，每条带数字或来源 |
| 3. 动作 | 标的 + 做什么 + 触发条件/价位 | ≤5 条，无动作写「无需操作」 |
| 4. 数据健康 | 会影响本场结论的缺口 | ≤5 条，每项「缺什么 → 哪条判断作废」 |

数据健康额外口径（`DUTY_OUTPUT_CONTRACT` 内）：不写熔断次数、provider 名、内部字段名；
与本场结论无关的标的不写；官方日K在收盘前落后一交易日不算故障。

## 二、结构化提交（`submit_duty_briefing`）

正文之外，模型必须在收口前调用 `submit_duty_briefing`：

```json
{
  "conclusion": "今天不动，明天等低开",
  "evidence":  ["组合 +0.8%，白酒贡献最大"],
  "actions":   ["002467 减半，跌破 4.6 执行"],
  "data_health": ["北向快照滞后 → 资金判断作废"]
}
```

- 工具做归一化：去 markdown 标记、去空条目、结论必填（空则抛错让模型重试）、
  条目截断 200 字、最多 8 条
- 结果落进 `tool_execution` 账本（`arguments` 存全量参数），
  调度器按 `run_id` 取**最后一次成功提交**（模型可能先交草稿再改）

## 三、报告落盘

`report_service._compose_ops_briefing` 用结构化提交生成固定四段：

```
# {标题}
> 结论：{briefing.conclusion}

## 依据      ← briefing.evidence + 指数/持仓/自选快照表 + 例外
## 动作      ← briefing.actions（无则「无需操作」）
## 数据健康  ← briefing.data_health
## 执行约束  ← 固定合规声明
```

- 模板章节元数据同步为 `["结论", "依据", "动作", "数据健康", "执行约束"]`
- 报告 payload 新增 `briefing` 字段，前端可直接取结构化四段
- **回退**：没有结构化提交时仍输出四段，「依据」里附一段「值班原文」，
  并在结论下方标注「本轮未提交结构化值班结论」

## 四、旧任务自动升级

四段改造前的旧文案都带 `【输出】≤600 字` / `≤900 字`，且不含「固定四段」。
`list_tasks()` 据此判定并升级到新 prompt（不再维护精确文案集合），
用户自己改过的文案（两者都不匹配）不会被覆盖。

## 五、测试

- `tests/test_duty_briefing.py`：归一化/校验、账本提取、报告四段、无提交回退、
  结论不再被标题行污染
- `tests/test_scheduler.py`：旧文案升级、四段契约注入

## 六、已知遗留

- 历史报告（改造前落盘）仍是旧骨架，不做回填
- 前端报告页目前按 markdown 渲染四段即可；如需卡片化，读 `payload.briefing`
