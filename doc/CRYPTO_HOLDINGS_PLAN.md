## 2. 六个必须先定的问题

### D1. 币种怎么办（最核心）

**先说一个已存在的 bug**：现在是 `market_value = 现价 × 数量`，**不带币种**；
`summarize_portfolio` 直接相加，前端 `money()` 统一加 `¥`。
所以「总资产」里其实混着 人民币（A股）+ 港币（港股）+ 美元（美股）——
加了加密货币只是把这个问题从"看不出来"变成"必须解决"。

**决策：两层 —— 分币种小计（主）+ 折合总额（辅，只作分母）。**

| 层 | 内容 | 依赖汇率 |
|---|---|---|
| **主：分币种小计** | `¥ 人民币` / `$ 美元` / `₮ USDT` 三笔，**原币原值**直接展示 | ❌ 不依赖 |
| **辅：折合总额** | 折算成人民币，**只用于**权重分母、单标的上限、组合体检 | ✅ 依赖 |

**为什么不是"只分开"**：没有分母 → 权重、单标的上限、组合体检全部失效（"BTC 占组合多少"无法回答）。
**为什么不是"只折算"**：汇率挂了整页报废，而且看不出钱分散在几个币种。

**汇率口径：按「当天汇率」折算，且折算值不落库。**

| 项 | 处理 |
|---|---|
| `holding_position` 新增 | `currency`（`CNY`/`HKD`/`USD`/`USDT`）、`market_value_native`（**原币**市值，这是唯一真相） |
| `market_value` | **不再存折算值**，改为读取时按当天汇率实时计算（存下来就等于把汇率冻死了） |
| 汇率来源 | **open.er-api.com**（实测可达，2026-10-24 USDCNY = **6.684864**）；`USDT/USD` 单独取（默认 1.0，脱锚时按实价） |
| 缓存 | **按日缓存**：同一天复用同一份汇率（含 `as_of` 日期），跨零点自动重取；日内允许手动刷新 |
| 页面标注 | `当日汇率 · 2026-10-24 · USD/CNY 6.6849`（是日期，不是"1 小时前"） |
| 汇率缺失 | 分币种小计**照常**；折合总额显示 `—`；权重退化为「币种内占比」（**不编数、不按 1:1 硬算**） |

**盈亏口径要分清（重要）**：

- **价格损益** = (现价 − 成本) × 数量，**用原币算**，不受汇率影响 → 这才是"选股/择时"的能力
- **汇兑损益** = 原币市值 × (今日汇率 − 建仓日汇率) → 单独算、单独展示，**不混进价格盈亏**

否则汇率涨跌会污染对交易能力的判断（"我选股很准，其实只是人民币贬值了"）。

展示示例（原型第 ① 屏）：

```
总资产（折合） ¥194,158          ← 分母
¥ 人民币 ¥93,600 (48.2%)   $ 美元 $5,715 (19.7%)   ₮ USDT ₮9,328 (32.1%)
当日汇率 2026-10-24 · USD/CNY 6.6849 · USDT/USD 1.0000
```

> 顺带把港股/美股的混算一起修掉（同一套 `currency` 字段），否则港股仓位永远算不准。

### D2. 市场识别会误判（这是 bug 点）

现在 `frontend/src/utils/market.ts`：

```ts
if (/^[A-Z]{1,5}$/.test(s)) return "US";   // ← BTC / ETH / SOL 全被判成 US
```

**决策**：`inferMarket` 增加 crypto 分支，且**以 `stock_master.market` 为准**（后端已返回 `market` 字段），`inferMarket` 只作兜底。
crypto 判定顺序：后端 market → 已知币种表 → 正则。

### D3. 数量与价格精度

- 数量：`0.08 BTC`（小数），股票是整数股
- 价格：BTC `80,895.7`（1 位）；小币 `0.00001234`（8 位）
- **决策**：价格按量级自适应（≥1000 两位 / ≥1 两位 / <1 保留 6 位有效数字）；数量统一保留最多 8 位小数、去掉尾随 0

### D4. 排序与分组

**决策：默认按市值混排**（不分段），提供**市场 chip 筛选**（全部 / A股 / 港股 / 美股 / 加密货币）。
理由：混排才能看出"钱压在哪"；分段会让"总仓位"失去意义。

### D5. 刷新节奏

股票靠轮询 60s；加密货币 7×24 且波动快，60s 太钝。

**决策**：`quote` 缓存按 market 分 TTL —— `CRYPTO: 10s`、其它 `60s`；前端轮询仍 60s（P0 不改轮询），
加密货币页面单独打开时再降频（P2 再考虑 WS）。

### D6. 权重与风控

- 权重：统一用 **CNY 折算后市值** 计算（`computeWeights` 不用改）
- 单标的权重上限（风险策略 `single_position_max_weight_pct`）：对币**同样生效**
- 加密货币的"行业集中"暂时不映射到赛道（stage 1 不做），只算单标的上限

## 6. 验收标准（DoD）

1. 加 0.08 BTC + 1.2 ETH 到持仓 → 权重、总市值、盈亏与手算一致（误差 < 0.01%）
2. 汇率源挂掉 → 加密货币市值显示 `—`、顶部黄条提示，**不出现 0 或编造值**
3. `BTC` 不再被识别成美股（`inferMarket` 回归用例）
4. 自选加 BTC → 分组可选「加密货币」，现价显示 `$80,895.7`
5. 混排排序正确（按 CNY 折算市值），chip 筛选可用
6. 现有股票持仓行为零回归（全部旧用例通过）
7. 港股/美股不再与人民币直接相加：`currency` 正确、分币种小计正确、折合总额正确
8. 汇率缺失时：三个小计照常、折合总额为 `—`、权重退化为币种内占比并有标注
9. 折算值不落库：改库里的 `market_value` 不影响展示；隔天汇率变化后总资产随之变化
10. 盈亏拆分：价格损益（原币）与汇兑损益分开，价格损益不随汇率变动

### 9.1 衍生品能力
`get_crypto_derivatives(symbol)` → Gate 永续：

| 字段 | 说明 |
|---|---|
| `funding_rate` / `funding_annualized_pct` | 单次费率与年化（按 8h 结算折算） |
| `funding_percentile_90d` | 当前费率在近 90 次结算中的分位（>80 = 多头拥挤） |
| `open_interest_usd` | 持仓量（美元） |
| `long_short_account_ratio` / `long_short_taker_ratio` | 散户口径 / 主动买卖 |
| `top_trader_long_short_ratio` | 大户多空比（与散户背离时最有信息量） |
| `liquidations_24h` | 近 24h 多/空清算（美元） |
| `maintenance_rate` / `mark_price` / `index_price` | 强平相关 |

派生值（年化、分位）与原始字段一起返回，**不做结论**，由模型自己判断。
60s 缓存；非标的表内的币直接 `degraded`，不臆造。

### 9.3 新增持仓弹窗
- 后端 `POST /api/holdings`：按「现价优先、否则成本价」算**原币**市值入库，币支持小数数量
- 前端 `AddHoldingDialog`：搜标的（防抖 300ms）→ 选市场自动识别 → 填数量/成本 →
