Copilot · Agent Loop 展示升级

从「平铺步骤流」升级为「可折叠的思考→工具→观察 循环」，对齐 DSH / Claude Code 的 agent loop 表现。
要解决什么：现在思考、工具、结果是一条条平铺下来的，没有「这一个问题到底转了几圈」的概念。 一轮回答可能有 5 次工具调用、8 段思考，全部铺开会把答案挤到屏幕外；全部折叠又看不见 agent 在干什么。
升级点：① 整条 loop 折成一行统计；② 展开后是「思考 → 工具 → 思考 → 命令 → 思考」的交错流； ③ 工具输出默认 3 行可展开；④ 命令执行单独用终端块；⑤ 失败/降级一眼可见。
① 现状平铺：看不出轮次，也看不出每条工具的结果

三档状态：✓ 成功（绿）/ ! 降级（琥珀，部分可用）/ ✕ 失败（红）。降级不能当失败藏起来 —— 它意味着「结论有一部分不成立」。
⑥ 怎么落地到现有代码不推倒重来：在 steps 上扩两种节点 + 一层 loop 外壳
现状升级后
steps: {kind:"reasoning" | "tool"}[] 加 kind:"command"（sandbox bash）+ 每个节点带 status / durationMs / output / args
平铺渲染（.tl-steps） 外面套一层 .loop：标题栏（步数/工具数/时长/轮次）+ 可折叠正文
工具只显示名字 工具行 = 名字 + 单行参数摘要 + 耗时 + 状态；输出默认 3 行，点开全文
bash 也当普通工具 单独 .cmd-node：命令行 + 深色 stdout 块 + exit code
无轮次概念 后端 reasoning 事件带 round（或前端按「思考→工具」序列自行切分）
需要的后端配合很小：reasoning 事件补 round、tool_result 补 duration_ms 与结构化 output、 bash 调用标记 kind:"command"。其余都是前端渲染层。
