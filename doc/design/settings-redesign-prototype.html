当前默认落在「外观」——和一进设置最该确认的「模型有没有连上」没有关系。
1
「提供商」和「默认模型」拆两页。 连完 Key 要跳另一页选模型；两页各有一个「测试连接」，能力开关（思考模式）夹在模型页里。
2
没有「当前生效状态」的入口。 用哪个模型、有没有 key、哪些数据源缺凭证、runtime 是否降级 —— 只散落在第 14 项「运行诊断」。
3
危险配置和日常配置同级。 风控上限（直接影响建议仓位）、MCP（能接外部工具）、交易护栏（只读）和「外观」同一个层级。
4
数据源 / 情报边界糊。 数据源页管 provider 开关，情报页又管「新闻搜索 / 舆情」开关，同一件事两个入口。
5
保存心智不统一。 有的即时生效、有的「保存生效」、MCP 还标着「下一轮对话生效」，用户不知道刚才那下到底生效没有。

6 · 三条交互规范（全站统一）

保存模型：即时生效

行内显示「已保存 ✓」，不再有底部大保存按钮。

  • ·例外必须写明时机：
    下一轮对话生效

每个值都带影响

改之前就知道会动到什么，而不是改完才看结果。

  • ·百分比类：列出受影响的持仓
  • ·开关类：一句话说清开/关差别

危险操作前置

红框区 + 二次确认弹窗列出「将失去什么」。

  • ·不可逆的排在最后
  • ·按钮不放在常规行内

7 · 落地对照：现有组件怎么搬

现有新位置改动工作量
提供商模型与智能 → 提供商与「默认模型」合并同页小：搬组件
默认模型模型与智能 → 当前模型加影响说明、测试结果内联中
技能 / 记忆 / MCP模型与智能 → 高级默认折叠，保持原组件小
数据源 + 情报数据与情报合并成一个 provider 目录；新闻/舆情降为该目录能力中偏大
风控 + 交易画像与风控上限类 + 危险操作分区；加影响预览中
通知通道通知与提醒补「什么事件触发」清单小
运行诊断系统与诊断健康度上移到概览；这里只留排障小
外观 / 工作区本机（导航下方独立组）不与业务配置混排小
—概览（新页）健康度 + 必配清单 + 最近变更，需新接口聚合中
