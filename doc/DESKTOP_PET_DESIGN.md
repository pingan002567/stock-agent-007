# 消息提示桌面小宠物 · 设计稿

> 状态：**设计已确认**（造型 + 交互策略已定，待实现 P0）
>
> 已确认：① 形象＝趴着的客服柴犬；② 常驻右下角 + 可拖拽 + 松手吸附边缘；
> ③ 气泡**只在 alert / done / error 弹**，unread 只出角标。
> 目标：做一个「消息提示」性质的桌面小宠物 —— 不说话、不挡操作，用姿态和一个小气泡告诉你：
> 有没有新消息、Agent 是不是在跑、有没有高优告警。

## 0. 角色设定：客服柴犬（生成插图版）

桌宠 = **App 图标里那只客服柴犬**（耳麦 + 领结）。形象来自 AI 生成的一套动作图，
5 个状态各用一张，已去背景、去水印，放在 `frontend/src/assets/pet/`：

| 状态 | 图 | 说明 |
|---|---|---|
| `idle` | `idle.png` | **趴着**吐舌，日常待机 |
| `working` | `working.png` | 托腮皱眉思考 |
| `done` | `done.png` | 双手举起欢呼 |
| `alert` | `alert.png` | 惊讶张嘴，带 `!` 标记 |
| `error` | `error.png` | 扶额，带 `…` |

**素材处理（可复现）**：原始图在 `~/Downloads/生成柴犬动作图片 (N).png`，
处理成 264×216（2x）透明 PNG：

1. **抠背景**：背景是纯奶油色，但狗自己的白胸毛和背景只差 8/255 ——
   直接全局抠色会把狗抠出洞。做法是**从边缘 flood fill**（形态学重建），
   并且把**梯度大的像素排除在"背景"之外**（描边屏障），flood 就穿不过轮廓。
2. **去水印**：「豆包AI生成」是浅灰描边字，位置在右下角固定区域。
   用一张无水印处的图求出它的包围盒，只在这块里清「浅灰细线」，
   保护狗的深色描边。
3. **统一画布**：裁到主体包围盒 → 等比缩放 → 264×216 画布**底部对齐**，
   这样不同姿态的脚底在同一条基线上。

配色（取样自图标）：橙 `#EEBF84` · 深棕 `#604C38` · 奶白 `#FDF7ED`。

## 1. 形态与定位

```
┌─ 屏幕右下角 ─────────────────────────────┐
│                                          │
│                          ┌────────────┐  │
│                          │   ● 3      │  │  ← 未读角标（仅角标，不弹气泡）
│                          │  ╱\  ╱\    │  │
│                          │ ( ◕ω◕ )～～ │  │  ← 趴着的柴犬 132×108
│                          └────────────┘  │
│                                ↑ 24px     │
└──────────────────────────────────────────┘
```

| 项 | 决定 | 理由 |
|---|---|---|
| 窗口尺寸 | **132×108**（趴姿是宽扁的，正好包住本体） | 透明区域越大越挡操作，窗口越小越好 |
| 气泡 | **临时把窗口撑到 320×150 并锚定左下角**，4~8 秒后缩回 | 常驻大窗会挡住桌面；气泡是瞬时的 |
| 位置 | 默认右下角，距边缘 24px；**可拖**，松手吸附边缘 | |
| 置顶 | `alwaysOnTop: true` + `visibleOnAllWorkspaces` | 切桌面也能看到 |
| 不抢焦点 | `focus: false`，点击宠物才 `set_focus` 主窗口 | 不能打断你正在打的字 |

## 2. 状态机（设计核心）

一次只显示一个状态，按优先级取最高的。

```
优先级  状态        触发                          表现
────────────────────────────────────────────────────────────────
 1     alert      盯盘 high 事件               橙色抖动 3 次 + 气泡「⚠ 高优告警」
 2     error      run 失败                     垂头 + 红点，气泡显示错误摘要
 3     done       一轮 run 收到 final          举手 + 「✅ 回答好了」，8s 后回 idle
 4     working    copilotStreaming = true      转圈/打字动画 + 蓝点
 5     unread     有未读会话或事件             眨眼 + 红色角标数字
 6     idle       无事件 ≥60s                  呼吸缩放（4s 一次），闭眼
────────────────────────────────────────────────────────────────
 专注   focus      用户手动开启                 完全隐藏，只留 1px 提示条
```

**数据来源全部现成**，不需要新接口：

| 状态 | 来源（前端已有） |
|---|---|
| working / done | `useCopilotChat().copilotStreaming` + 新消息到达 |
| unread | `useMonitorUnread().unreadCount` |
| alert | `appDataCache.inboxSummary.high_count`（顶栏那个红点用的同一个） |
| error | `useToast` 的 `type === "error"` |

## 3. 交互

| 操作 | 行为 |
|---|---|
| **单击** | 打开对应内容（有告警→事件详情；有未读→那条会话；否则→主窗口），并 `show + focus` 主窗口 |
| **双击** | 显示 / 隐藏主窗口 |
| **右键** | 小菜单：`静音 30 分钟` / `打开设置` / `隐藏到托盘` / `位置重置` |
| **拖拽** | 移动，松手吸附屏幕边缘 8px 内 |
| **悬停 1s** | 气泡显示最近一条消息摘要（不跳转） |
| **点击气泡** | 同单击 |

**5 个姿态（柴犬版，全部只改眼睛/耳朵/嘴）**

| 状态 | 眼睛 | 耳朵 | 嘴 | 附加 |
|---|---|---|---|---|
| `idle` | 闭成 `^ ^` | 放松、略外八 | 微笑弧线 | 呼吸缩放 1 → 1.03（4s） |
| `working` | 睁眼看前方 | 竖起、略前倾 | 一条横线（专注） | 耳麦亮一个蓝点；身侧三个点依次跳 |
| `done` | 弯成 `^ ^` | 上扬 | 张嘴笑 | 头顶冒 ✅（1.2s 浮起淡出） |
| `alert` | 瞪圆（瞳孔缩小） | 笔直竖起 | 小 `o` 形 | 额头一滴汗；整体左右抖 3 次（±3px） |
| `error` | 半垂眼 + 八字眉 | 下垂（向外折） | 下弯 | 头顶冒「…」灰点，3s 后回 idle |

**尾巴**（趴姿新增）也参与情绪：

| 状态 | 尾巴 |
|---|---|
| idle / working | 上翘，静止（working 时轻微摆） |
| done | **左右摇**（±8°，0.7s 一次） |
| alert | 竖直炸毛（比常态高） |
| error | 垂到地面 |

## 5. 技术方案（基于现有代码）

### 5.1 新窗口

`tauri.conf.json` 增加第二个 window：

```jsonc
{
  "label": "pet",
  "title": "Stock Agent",
  "width": 96, "height": 96,
  "transparent": true, "decorations": false, "shadow": false,
  "alwaysOnTop": true, "skipTaskbar": true, "resizable": false,
  "focus": false, "create": false,        // 与主窗口一致：运行时 from_config 建
  "visible": false
}
```

`lib.rs` 复用现有的 `WebviewWindowBuilder::from_config`（第 127 行已经在用同一个模式），
加启动参数 `--pet` 或托盘菜单项「显示桌宠」来开它。

### 5.2 主窗口 ↔ 宠物

```
主窗口                                  宠物窗口
useCopilotChat / monitorUnread   ──emit_to("pet", "pet-state", payload)──▶  渲染状态
  onAction(open, {sessionId})     ◀──emit_to("main", "pet-action", {...})──  单击/双击
```

Tauri 2 的 `emit_to(label, event, payload)` 是现成能力，不用加插件。
（备选：`localStorage` + `storage` 事件，同源可用，但实时性差一点，且拿不到窗口状态。）

### 5.3 不挡操作

- 窗口只有 96×96 → 遮挡面积最小
- `set_ignore_cursor_events(true)` 只在「静音 / focus 模式」时开（平时要能点）
- 拖动时用 `start_dragging()`（Tauri 内置），不要自己算坐标

### 5.4 位置记忆

`outer_position()` 存到配置文件；启动时按「上次位置」→ 不在任何屏幕内则回落右下角。

### 5.5 降级

- 非 Tauri（浏览器 / web）→ 整个功能不启用
- 设置里：`显示桌宠` 开关 / `静音 30 分钟` / `尺寸`（小 96 / 中 112）/ `位置重置`

## 5.6 实现状态（P0 已完成）

| 能力 | 状态 | 说明 |
|---|---|---|
| 透明置顶窗口 | ✅ | `tauri.conf.json` 里 label=`pet`；需 `app.macOSPrivateApi: true`（macOS 透明窗口必需） |
| 窗口定位 | ✅ | 用 `Monitor::work_area()`（已排除菜单栏与 Dock），右下角 24pt |
| 状态桥 | ✅ | 主窗写 `localStorage['pet.state']`，桌宠窗靠 `storage` 事件收（同源，无需插件） |
| 5 个姿态 | ✅ | `src/assets/pet/{idle,working,done,alert,error}.png`（生成图，已去背景/水印） |
| 气泡 | ✅ | 只在 alert/done/error；8s 自动收；弹出时 `pet_resize` 把窗口撑到 300×200 并锚定右下角 |
| 角标 | ✅ | 高优待办数；>9 显示 `9+` |
| 单击叫出主窗 | ✅ | `pet_focus_main` |
| 拖动 + 位置记忆 | ✅ | `pet_start_drag`（松手才返回）→ 存 `localStorage['pet.pos']` |
| 浏览器预览 | ✅ | `?pet=1` 可直接看桌宠 UI（设计/联调用） |

**踩过的坑**（都记在这份文档里）：

0. **新窗口必须显式授权，否则所有 invoke 静默失败**（这是「点击没反应」的真正原因）
   - `src-tauri/build.rs` 的 `AppManifest::commands([...])` 要列出每个 app 命令，
     否则不会生成 `allow-<cmd>` 权限
   - `capabilities/*.json` 的 `windows` 要加 `"pet"`，`permissions` 要加对应的 `allow-*`
   - 两处任一漏掉，`invoke` 会被拒绝；而前端若用 `.catch(() => {})` 吞掉错误，
     表现就是「点了完全没反应」——**调试时一定先确认 invoke 能不能通**


1. macOS 上透明窗口必须开 `app.macOSPrivateApi`，否则窗口是黑的/不透明；
2. `usePetBridge` 依赖 `useAppState`，必须挂在 `AppStateProvider` **内部** ——
   挂在 `App` 函数体顶部会把整棵树打成白屏（Provider 是 App 自己渲染的）。
