# 消息提示桌面小宠物 · 设计稿

> 状态：**设计已确认**（造型 + 交互策略已定，待实现 P0）
>
> 已确认：① 形象＝趴着的客服柴犬；② 常驻右下角 + 可拖拽 + 松手吸附边缘；
> ③ 气泡**只在 alert / done / error 弹**，unread 只出角标。
> 目标：做一个「消息提示」性质的桌面小宠物 —— 不说话、不挡操作，用姿态和一个小气泡告诉你：
> 有没有新消息、Agent 是不是在跑、有没有高优告警。

## 0. 角色设定：客服柴犬（生成插图版）

桌宠 = **App 图标里那只客服柴犬**（耳麦 + 领结）。形象来自 AI 生成的一套动作图，
5 个状态各用一张，已去背景、去水印，放在 `frontend/src/assets/pet/`：

| 状态 | 图 | 说明 |
|---|---|---|
| `idle` | `idle.png` | **趴着**吐舌，日常待机 |
| `working` | `working.png` | 托腮皱眉思考 |
| `done` | `done.png` | 双手举起欢呼 |
| `alert` | `alert.png` | 惊讶张嘴，带 `!` 标记 |
| `error` | `error.png` | 扶额，带 `…` |

**素材处理（可复现）**：原始图在 `~/Downloads/生成柴犬动作图片 (N).png`，
处理成 264×216（2x）透明 PNG：

1. **抠背景**：背景是纯奶油色，但狗自己的白胸毛和背景只差 8/255 ——
   直接全局抠色会把狗抠出洞。做法是**从边缘 flood fill**（形态学重建），
   并且把**梯度大的像素排除在"背景"之外**（描边屏障），flood 就穿不过轮廓。
2. **去水印**：「豆包AI生成」是浅灰描边字，位置在右下角固定区域。
   用一张无水印处的图求出它的包围盒，只在这块里清「浅灰细线」，
   保护狗的深色描边。
3. **统一画布**：裁到主体包围盒 → 等比缩放 → 264×216 画布**底部对齐**，
   这样不同姿态的脚底在同一条基线上。

配色（取样自图标）：橙 `#EEBF84` · 深棕 `#604C38` · 奶白 `#FDF7ED`。

## 1. 形态与定位

```
┌─ 屏幕右下角 ─────────────────────────────┐
│                                          │
│                          ┌────────────┐  │
│                          │   ● 3      │  │  ← 未读角标（仅角标，不弹气泡）
│                          │  ╱\  ╱\    │  │
│                          │ ( ◕ω◕ )～～ │  │  ← 趴着的柴犬 132×108
│                          └────────────┘  │
│                                ↑ 24px     │
└──────────────────────────────────────────┘
```

| 项 | 决定 | 理由 |
|---|---|---|
| 窗口尺寸 | **132×108**（趴姿是宽扁的，正好包住本体） | 透明区域越大越挡操作，窗口越小越好 |
| 气泡 | **临时把窗口撑到 320×150 并锚定左下角**，4~8 秒后缩回 | 常驻大窗会挡住桌面；气泡是瞬时的 |
| 位置 | 默认右下角，距边缘 24px；**可拖**，松手吸附边缘 | |
| 置顶 | `alwaysOnTop: true` + `visibleOnAllWorkspaces` | 切桌面也能看到 |
| 不抢焦点 | `focus: false`，点击宠物才 `set_focus` 主窗口 | 不能打断你正在打的字 |

## 2. 状态机（设计核心）

一次只显示一个状态，按优先级取最高的。

```
优先级  状态        触发                          表现
────────────────────────────────────────────────────────────────
 1     alert      盯盘 high 事件               橙色抖动 3 次 + 气泡「⚠ 高优告警」
 2     error      run 失败                     垂头 + 红点，气泡显示错误摘要
 3     done       一轮 run 收到 final          举手 + 「✅ 回答好了」，8s 后回 idle
 4     working    copilotStreaming = true      转圈/打字动画 + 蓝点
 5     unread     有未读会话或事件             眨眼 + 红色角标数字
 6     idle       无事件 ≥60s                  呼吸缩放（4s 一次），闭眼
────────────────────────────────────────────────────────────────
 专注   focus      用户手动开启                 完全隐藏，只留 1px 提示条
```

**数据来源全部现成**，不需要新接口：

| 状态 | 来源（前端已有） |
|---|---|
| working / done | `useCopilotChat().copilotStreaming` + 新消息到达 |
| unread | `useMonitorUnread().unreadCount` |
| alert | `appDataCache.inboxSummary.high_count`（顶栏那个红点用的同一个） |
| error | `useToast` 的 `type === "error"` |

**5 个姿态（柴犬版，全部只改眼睛/耳朵/嘴）**

| 状态 | 眼睛 | 耳朵 | 嘴 | 附加 |
|---|---|---|---|---|
| `idle` | 闭成 `^ ^` | 放松、略外八 | 微笑弧线 | 呼吸缩放 1 → 1.03（4s） |
| `working` | 睁眼看前方 | 竖起、略前倾 | 一条横线（专注） | 耳麦亮一个蓝点；身侧三个点依次跳 |
| `done` | 弯成 `^ ^` | 上扬 | 张嘴笑 | 头顶冒 ✅（1.2s 浮起淡出） |
| `alert` | 瞪圆（瞳孔缩小） | 笔直竖起 | 小 `o` 形 | 额头一滴汗；整体左右抖 3 次（±3px） |
| `error` | 半垂眼 + 八字眉 | 下垂（向外折） | 下弯 | 头顶冒「…」灰点，3s 后回 idle |

**尾巴**（趴姿新增）也参与情绪：

| 状态 | 尾巴 |
|---|---|
| idle / working | 上翘，静止（working 时轻微摆） |
| done | **左右摇**（±8°，0.7s 一次） |
| alert | 竖直炸毛（比常态高） |
| error | 垂到地面 |

## 4.5 动态化：换成关键帧素材包 + sprite 动画

素材换成 `~/Downloads/柴犬关键帧`（76 张生成图），用 `scripts/pet_assets.py` 管线处理：

```
python3 scripts/pet_assets.py       # 一键重跑，约 10s
```

**管线做的四件事**（每步都是踩过坑才定下来的）：

1. **去背景**：只去掉「与画面边缘连通」的那片背景（形态学重建），
   并把梯度大的像素排除出"背景"（描边屏障）—— 否则白胸毛会被挖出洞。
2. **去浅色阴影**：素材自带的地面阴影是"很亮的柔光"，在深色桌面上会变成一块白垫子。
   第二道 flood 把「接近背景 或 很亮」的像素也当可通行，仍然靠梯度当屏障，
   能吃掉阴影但吃不到被描边围住的胸毛。落地阴影改用 CSS `drop-shadow` 补。
3. **归一化对齐**：循环帧不是同一套骨骼渲染的，包围盒在 1425×1915 ~ 1559×1981 之间抖。
   - **头部锚定**：取主体上部 30% 的 alpha 质心做水平锚点（四足循环里头部最稳，
     用整只包围盒中心会让跑步左右漂）
   - **组级解析缩放**：按「头到最左 + 头到最右」算所需宽度，铺之前就保证不溢出
     （铺完再量，量到的是已裁过的结果，永远看不出溢出）
   - 底边对齐：脚踩同一条线
4. **打包**：循环帧打成横向 sprite sheet（一次请求、一次解码、CSS `steps()` 播放），
   静态帧单独出 WebP(q82)。**29MB → 208KB**。

**播放结构**

| 状态 | 资源 | 播放 |
|---|---|---|
| idle | `loop-idle-breathe`（3 帧） | 1.9s 循环；每 4.5~9s 叠播一次 `blink`(0.42s) 或 `tilt`(0.62s) |
| working | `loop-run`（8 帧） | 0.8s 循环 |
| done | `done-1..3` | 700ms 交叉淡入 |
| alert | `alert-1..2` | 900ms 交叉淡入 |
| error | `error-1..2` | 1400ms 交叉淡入 |

> 待机 8 帧原本是「呼吸 + 眨眼 + 歪头」三段拼的，整段循环会让它每 1.4s 眨一次眼（太频繁），
> 所以拆成「呼吸常驻 + 眨眼/歪头偶尔插播」。

**几何稳定性**（这类窗口最容易翻车的地方）：
窗口大小随气泡切换（132×132 ↔ 300×236）。位置一律由 JS 里缓存的「位置+尺寸」
按**右下角不动**推出来，**不去读 `outer_size()`** —— 那个值异步生效，
和 `set_size` 抢起来会把窗口推到屏幕中间（实测发生过两次）。

## 4.6 三层播放 + 交互（P1/P2 已完成）

### 播放分层

```
拖动中      → 走路循环（8 帧）
一次性动作  → 点击「开心拍掌」/ 闲时「摸鱼看手机·伸懒腰·歪头·打哈欠」，播完自动回基础循环
睡眠        → 空闲 ≥3 分钟：闭眼静帧（任何交互/事件立刻醒）
基础循环    → idle 呼吸 / working 跑步 / done 摇尾 / alert·error 静帧淡入
```

优先级：拖动 > 一次性动作 > 睡眠 > 基础循环。

### 一次性动作池

| 触发 | 动作 | 素材 |
|---|---|---|
| 单击 | 开心拍掌 | `clap-1/2`（380ms 交叉淡入，停 1s）|
| idle 闲时（每 18~35s 随机） | 摸鱼看手机 / 伸懒腰 / 歪头 / 打哈欠 / 拍掌 | 对应关键帧 |
| 空闲 ≥3 分钟 | 打哈欠 → 睡眠（闭眼静帧） | `yawn-1` → `sleep-1` |

### 右键菜单（P2）

| 项 | 行为 |
|---|---|
| 安静模式 | 只出角标、不弹气泡（`pet.quiet`） |
| 大小：小/中/大 | 110 / 132 / 160 pt（`pet.size`），气泡窗口高度跟随 |
| 重置位置 | 清 `pet.pos.v3`，回到屏幕右下角 |
| 隐藏桌宠 | 关开关 + 隐藏窗口；**托盘菜单「显示桌宠」可恢复** |

### 素材规格（P2）

- 出图按 **3x**（画布 396，主体 360），显示 132pt → 2x/3x 屏都清晰
- 全部 WebP(q82)：循环 5 组 + 静态 11 张，**合计 608KB**
- 尺寸档位靠 CSS `transform: scale()` 缩放舞台（sprite 的 px 尺寸不变），不重出图

## 4.7 通知策略与引导

**状态优先级**：`error(8s) > working > done(8s) > alert(10s) > idle`

两个容易做错的地方，已经改掉：

- **alert 只在「高优数量增加」时触发**，不再是 `high_count > 0`
  —— 待办会一直存在，否则宠物永远惊恐脸。角标仍然常显示数量。
- **error 接的是 error toast**：出现新报错时播 8s 沮丧姿态，气泡显示报错摘要。
  此前 error 状态没有任何数据源。

**气泡内容**：done 用**最后一条助手回复的前 30 字**，不再是"这一轮已经跑完"这种废话。

**首次引导**：第一次出现时气泡提示「点我叫出主应用 · 拖动挪位置 · 右键设置」，10s 后自动收并写 `pet.guide=1`。

## 5. 技术方案（基于现有代码）

### 5.1 新窗口

`tauri.conf.json` 增加第二个 window：

```jsonc
{
  "label": "pet",
  "title": "Stock Agent",
  "width": 96, "height": 96,
  "transparent": true, "decorations": false, "shadow": false,
  "alwaysOnTop": true, "skipTaskbar": true, "resizable": false,
  "focus": false, "create": false,        // 与主窗口一致：运行时 from_config 建
  "visible": false
}
```

`lib.rs` 复用现有的 `WebviewWindowBuilder::from_config`（第 127 行已经在用同一个模式），
加启动参数 `--pet` 或托盘菜单项「显示桌宠」来开它。

### 5.2 主窗口 ↔ 宠物

```
主窗口                                  宠物窗口
useCopilotChat / monitorUnread   ──emit_to("pet", "pet-state", payload)──▶  渲染状态
  onAction(open, {sessionId})     ◀──emit_to("main", "pet-action", {...})──  单击/双击
```

Tauri 2 的 `emit_to(label, event, payload)` 是现成能力，不用加插件。
（备选：`localStorage` + `storage` 事件，同源可用，但实时性差一点，且拿不到窗口状态。）

### 5.3 不挡操作

- 窗口只有 96×96 → 遮挡面积最小
- `set_ignore_cursor_events(true)` 只在「静音 / focus 模式」时开（平时要能点）
- 拖动时用 `start_dragging()`（Tauri 内置），不要自己算坐标

### 5.4 位置记忆

`outer_position()` 存到配置文件；启动时按「上次位置」→ 不在任何屏幕内则回落右下角。

### 5.5 降级

- 非 Tauri（浏览器 / web）→ 整个功能不启用
- 设置里：`显示桌宠` 开关 / `静音 30 分钟` / `尺寸`（小 96 / 中 112）/ `位置重置`

| 一次性动作 | ✅ | 点击拍掌 / 闲时随机小动作 / 拖动播走路 |
| 睡眠 | ✅ | 空闲 ≥3 分钟闭眼 |
| 右键菜单 | ✅ | 安静模式 / 大小三档 / 重置位置 / 隐藏（托盘可恢复） |
| 气泡 | ✅ | 只在 alert/done/error；8s 自动收；弹出时 `pet_resize` 把窗口撑到 300×200 并锚定右下角 |
| 角标 | ✅ | 高优待办数；>9 显示 `9+` |
| 单击叫出主窗 | ✅ | `pet_focus_main` |
| 拖动 + 位置记忆 | ✅ | `pet_start_drag`（松手才返回）→ 存 `localStorage['pet.pos']` |
| 浏览器预览 | ✅ | `?pet=1` 可直接看桌宠 UI（设计/联调用） |

**踩过的坑**（都记在这份文档里）：

0. **新窗口必须显式授权，否则所有 invoke 静默失败**（这是「点击没反应」的真正原因）
   - `src-tauri/build.rs` 的 `AppManifest::commands([...])` 要列出每个 app 命令，
     否则不会生成 `allow-<cmd>` 权限
   - `capabilities/*.json` 的 `windows` 要加 `"pet"`，`permissions` 要加对应的 `allow-*`
   - 两处任一漏掉，`invoke` 会被拒绝；而前端若用 `.catch(() => {})` 吞掉错误，
     表现就是「点了完全没反应」——**调试时一定先确认 invoke 能不能通**


1. macOS 上透明窗口必须开 `app.macOSPrivateApi`，否则窗口是黑的/不透明；
2. `usePetBridge` 依赖 `useAppState`，必须挂在 `AppStateProvider` **内部** ——
   挂在 `App` 函数体顶部会把整棵树打成白屏（Provider 是 App 自己渲染的）。

## 9. 优化清单（基于 `~/Downloads/柴犬关键帧` 这套新素材）

### 9.1 素材事实（实测，不是估计）

| 项 | 数据 |
|---|---|
| 文件 | **76 张 PNG**：17 表情 + 27 姿态/过渡（01–44）+ 4 组循环各 8 帧 |
| 分辨率 | 2026×2069（部分 1472×1504），**RGB 无 alpha**，奶油底色 |
| 体积 | **≈29MB** |
| 压缩潜力 | 缩到 264×216 + WebP(q82) → **≈0.7MB（原体积的 2.3%）** |
| 循环帧对齐 | **未对齐**：`idle_01..08` 的主体包围盒在 1425×1915 ~ 1559×1981 之间抖，位置差 **130px**，帧间像素差 **27–51%** |
| 风格 | 软光感、细描边、带地面阴影 —— 与当前在用的那批（粗描边卡通）**不是同一套画风** |

**结论 1：循环帧不能直接播。** 它们是用图像模型生成的"关键帧"，不是同一套骨骼渲染的，
直接连播会像人物在抖/忽大忽小。必须做**包围盒归一化**（等比缩到同高 + 水平居中 + 底对齐）——
实测归一化之后 6 帧基本能连起来看了。

**结论 2：必须换画风或放弃新素材。** 两套图混用会一眼看出不是同一个东西。
新素材完整度远高于旧的（有循环、有表情、有过渡），建议**整体迁到新风格**。

### 9.2 优化项（按收益 / 成本排序）

#### P0 · 不做就白瞎了这套素材

1. **素材管线**（一次性脚本，可复现）
   去背景（边缘 flood + 描边/梯度屏障）→ 包围盒归一化 → 264×216 → WebP(q82) → 打包
   - 循环帧**打成 sprite sheet**（8 帧横排 1 张），一次请求一次解码，CSS `steps()` 驱动
   - 收益：29MB → 0.7MB；播放从「改 src」变成「GPU 位移背景图」，不掉帧
2. **用真循环替换现在的"换姿势"**
   - `idle` → 坐立待机循环（已有呼吸下沉 / 半闭眼 / 全闭眼 / 歪头）
   - `working` → 跑步循环
   - `done` → 跳跃欢呼 + 开心拍掌
   - `alert` → 惊讶抬爪
   - `error` → 无语扶额 / 委屈抱胸
3. **风格一次性切换**（旧 9 张下线）

#### P1 · 让它"有生命"

4. **状态机升级成三层**：`基础循环` + `一次性动作(one-shot)` + `表情层`
   - 规则：one-shot 播完自动回基础循环；高优先级可打断（alert > error > done > working > idle）
5. **点击反馈播一次 on-shot**：现在只是挤压回弹，可以播「开心拍掌」再回循环
6. **眨眼**：素材里已有 `44_眨眼过渡`，可以每 3–6s 插一次（成本极低、观感提升明显）
7. **随机小动作**：每 20–40s 随机播一次摸鱼看手机 / 伸懒腰 / 歪头疑惑 / 打哈欠
8. **拖动时播走路循环**（拖的过程有反馈）

#### P2 · 打磨

9. 3x 屏用 396×324 一套，避免糊
10. 空闲 ≥3 分钟 → 打哈欠 → 睡觉；有事件立刻醒
11. 窗口比例要改：新素材是**坐姿全身**（接近正方），当前 `132×108` 偏扁 → 改成 ~`150×150`，
    气泡窗口与锚点逻辑随之调整
12. 角标贴耳朵、气泡避让头部（现在角标在窗口角上，离头较远）
13. 设置项：显示/隐藏、安静模式（只在 alert 出现）、大小档位

### 9.3 已知风险

- **归一化后仍会有轻微"呼吸式缩放"**（各帧头部大小不完全一致）→ 用 60ms 交叉淡入掩盖
- 素材是 AI 生成的，个别帧的**爪子/尾巴连接处**可能有瑕疵，放大看才发现；264px 尺寸下大概率看不出来
- 循环帧转 sprite sheet 后**不便单独替换**，需保留原始 PNG 以便重跑管线

### 9.4 建议顺序

**先做 P0 的 1+2**（素材管线 + idle/working 真循环）—— 这一步就能把观感从
"会换姿势的贴图"变成"真的在动"，且不依赖后面的状态机改造。
